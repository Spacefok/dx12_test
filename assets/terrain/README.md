# Terrain heightmaps

These four tiles are generated by the repository's standalone Python terrain
generator. It combines deterministic value noise, ridges, and a winding valley.
Python 3 and its standard library are the only generator dependencies; the
renderer loads the checked-in tiles directly and does not require Python.

Regenerate the supplied terrain from the repository root:

```powershell
py -3 tools/generate_terrain.py --seed 1337
```

`1337` is also the default seed. Use `--seed` for a different terrain or
`--output <directory>` to export elsewhere. Generation validates sample counts
and shared borders before writing the tiles, and verifies every output size.

## Raw format and coordinates

- Files: `height_0_0.r16`, `height_1_0.r16`, `height_0_1.r16`, `height_1_1.r16`.
  The filename indices are `X_Z`, each in `0..1`.
- Each tile is **129 x 129 unsigned 16-bit little-endian samples**, with no
  header, exactly **33,282 bytes** per file.
- Samples are row-major: X increases across a row; Z increases between rows.
  The sample at local `(x, z)` begins at byte `2 * (z * 129 + x)`.
- Convert a sample to world height with `y = sample / 65535.0 * 14.0` metres.
  Zero is world Y = 0; no signed offset or endian conversion beyond little-endian
  decoding is used.
- Each tile covers **32 x 32 metres**, with **0.25 metre** sample spacing.
  All four together cover **64 x 64 metres**, X and Z both from **-32 to +32**.
  Tile `(0, 0)` starts at world `(-32, -32)` in XZ; tile `(1, 1)` starts at `(0, 0)`.
- Adjacent tiles share one exact sample column or row. The complete heightmap
  contains **257 x 257 unique samples**, not 258 x 258. The four-way corner is
  identical in all four files.

To use tiles exported from another heightmap tool, preserve this layout and
scale. Export overlapping tile borders; independently generated tile edges
would introduce cracks even before LOD selection.
